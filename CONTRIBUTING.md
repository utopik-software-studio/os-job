# Contributing to OS::JOB

Contributions are welcome even while the original development is paused.

1. Search existing issues; describe the problem, expected behavior and reproduction steps.
2. For larger changes, open an issue before implementing.
3. Fork, create a focused branch and submit a pull request with a clear summary and manual test steps.
4. Do not submit personal CVs, recruiter details, real applications, database dumps, credentials or logs.
5. Keep local-first behavior and backwards compatibility in mind. Avoid introducing mandatory cloud dependencies.
6. Update documentation and roadmap when behavior changes. Version fixes can be batched into the next feature release unless urgent.

No response-time or merge guarantee is offered.
